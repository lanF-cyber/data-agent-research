# 第 3 周 · CoSQL 多轮问答实验

**研究目标**是在同题条件下比较 GPT-6 Sol 的提问、查库和交付流程，找出限制正确率的具体原因。本周从 32 问试跑推进到 502 问连续提问基线，对同一批 502 问复跑了自主查库与 MCP 流程，并从数据库核查两版实际给出的答案。

[五种方法的同题结果](../../README.md#同一批-101-问五种做法) · [读具体错例](cases.md) · [复算和实验代码](reproduce.md)

## 实验怎样推进

| 阶段 | 怎样测、为什么换 | 实际规模与结果 |
| --- | --- | --- |
| 跑通基线 | 先读 CoSQL 的题目、字段与参考查询，手动验证一段三轮问题，再逐问新开会话批量跑。 | 10 段、32 问通过 **23 问**。扩大到 29 段、101 问后通过 **75 问**。 |
| 让模型连续追问 | 在同一会话中按顺序发送问题，并把上轮 SQL 实际查到的结果交给下一轮。 | 同题 27 问中，逐问方法通过 **15 问**，连续方法通过 **17 问**。全 101 问通过 **77 问**。 |
| 扩大连续基线 | 保持做法，继续选完整对话，逐问保存模型 SQL 和实查结果。 | 300 问通过 **206 问**。追加 202 问通过 **137 问**，合计 **343/502**，覆盖 143 段、20 个数据库。 |
| 小测三种查库信息 | 在连续流程上分别加真实建表语句、字段值样例或脚本代查。 | 同一批 25 问，原流程复跑 **14/25**，加建表语句 **14/25**，再加值样例 **15/25**，建表语句加代查 **12/25**。代查实际触发 1 次。 |
| 给模型真实数据库 | 每段对话给独立目录和 SQLite 副本，模型用终端查看表和实际值。 | 12 问先导通过 **6 问**。随后在同一批 101 问通过 **53 问**，其中 96 问交出可执行 SQL。 |
| 改进自主查库开场 | 统一说明如何接续对象和条件，如何交最终 SQL，后续逐轮发原题。 | 先在 14 问中由 **5/14** 提升到 **11/14**，再跑其余 87 问，由 **48/87** 到 **64/87**。全批由 **53/101** 到 **75/101**。 |
| 让 MCP 参与交付 | 先让模型提交查询和表格，由 MCP 对值，再改为 MCP 自己执行最终 SQL 并展示结果。 | 定向试跑 13 问均收到核验表。Research 版同题 101 问收到 **98 张表**，原规则通过 **66 问**。 |
| 扩大 MCP 流程 | 开场补充计算精度、歧义处理和题目前提查证。Research 并发调度对话，每段内部逐轮进行。 | 完整复跑相同 502 问，交付 **500 张核验表**。此前用于调提示的 101 问在本批原规则通过 **70 问**，其余 401 问通过 **255 问**。 |

第一版把上轮结果写进下一条提示。自主查库版本只给数据库与开场说明，模型通过同一会话保留自己的查询记录。MCP 的工作是把最终 SQL 的查询结果送到用户面前，解决 SQL 已经查对、文字答案却抄错的问题。 [101 问明细](../../evidence/week-03/paired-101.csv) · [502 问样本和数据库版本](../../evidence/week-03/frozen-plan.json)

## 502 问的三种判分

| 评分及含义 | 连续提问基线 | 自主查库 + MCP |
| --- | ---: | ---: |
| **完整执行结果**。按题库参考 SQL 核对全表。 | **343/502（68.33%）** | **325/502（64.74%）** |
| **预先筛查的明确题**。在 422 问比较核心答案字段。 | 353/422（83.65%） | 341/422（80.81%） |
| **全部题按题意事后复评**。看实际答复、追问上下文和原库证据。 | **458/502（91.24%）** | **492/502（98.01%）** |

80 道事前标疑题照常跑。MCP 对能从题意或原库看出问题的 40 问处理得当 **30 问**。另 40 问的参考查询有疑点，MCP 有 **38 问**给出了符合库中事实的答复。事后复评把 502 问合在一起，36 问只有 MCP 版通过，2 问只有基线通过。

复评按问题需要匹配字段和值，允许有用的辅助列和有依据的等价解法。程序核对能直接验证的结果，需解释题意或参考有疑点的题由实验助手逐题判读并记录理由。两版同时改变了查库方式、提示和交付，所以这张表衡量整套流程的差异。 [本轮成绩](../../evidence/week-03/summary.json) · [事后复评逐题理由](../../evidence/week-03/answer-review/decisions.jsonl)

| 效率 | 连续提问基线 | 自主查库 + MCP |
| --- | ---: | ---: |
| 单问中位耗时 | 4.75 秒 | 9.22 秒 |
| 90% 的问题在该时长内完成 | 7.21 秒 | 21.91 秒 |
| 日志记录的总 token | 3,129,374 | 14,504,927 |

MCP 批次实际用时 28 分 48 秒。单问耗时和批次用时分别反映一问要等多久，以及并发跑完整批要多久。 [耗时与用量记录](../../evidence/week-03/verification.json)

## 基线 159 个结果差异从哪里来

基线有 **159/502** 问与参考执行结果不同。按每问最主要的差异归为 11 类。表中的占比以这 159 问为分母。

| 主要差异 | 问数 | 占比 | 读一个例子就能明白 |
| --- | ---: | ---: | --- |
| 返回字段与呈现方式 | 35 | 22.0% | 只问日期，结果表顺带给了战役名。 |
| 实体值和匹配方式 | 24 | 15.1% | 航班机场代码前有空格，直接匹配会漏记录。 |
| 题意与参考查询冲突或有歧义 | 22 | 13.8% | 性别存成 T/F，参考查询却搜索 True。 |
| 追问中的对象与条件 | 18 | 11.3% | 「那些人」应指上轮选出的人。 |
| 分组和聚合 | 13 | 8.2% | 应按洲计算平均值，却按国家逐条统计。 |
| 统计覆盖范围 | 12 | 7.5% | 求所有部门人数，人数为零的部门也应列出。 |
| 去重和计数单位 | 12 | 7.5% | 同名学生是两个人，按姓名去重会少算。 |
| 字段关系和连接方向 | 8 | 5.0% | 只从关系表的一侧查找，漏掉另一侧。 |
| 存储类型和缺失值 | 7 | 4.4% | 将整数生日当作日期字符串转换，排序错了。 |
| 筛选条件的作用范围 | 5 | 3.1% | 得先逐组算平均值，再按该平均值筛组。 |
| 并列与排序 | 3 | 1.9% | 多个对象并列第一，结果只给一个。 |

字段差异需要看多出的内容有没有改变实际答案。题库问题需要查清题面、参考 SQL 与数据哪个环节不一致。剩余的典型模型错误落在实体匹配、上下文接续、统计与连接逻辑。按 11 类逐题查证，才能知道应该改评分、改数据，还是改模型的查库方法。 [159 问归类清单](../../evidence/week-03/baseline-159.csv) · [题目、实际答案与预期](cases.md)
