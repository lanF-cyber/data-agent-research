# 数据 Agent 研究

## 第 3 周 · CoSQL 多轮数据库问答

在 CoSQL 上比较 GPT-6 Sol 的提问、查库和交付方式，探索如何让正确率逐步逼近 100%。用同一批问题对照实验，逐题查清模型、参考答案和评分规则各会造成哪些失分。

[本周报告](weeks/week-03/README.md) · [具体错例](weeks/week-03/cases.md) · [复算与代码](weeks/week-03/reproduce.md)

### 同一批 101 问，五种做法

| 做法 | 怎样问、怎样查 | 按原规则通过 | 可执行 SQL 或核验表 |
| --- | --- | ---: | ---: |
| 逐问新开会话 | 每次给表结构和前面问过的问题 | 75/101（74.26%） | 101 份 SQL |
| 同一会话追问 | 脚本执行上轮 SQL，将查出的结果带入下一问 | **77/101（76.24%）** | 101 份 SQL |
| 让模型自主查库 | 给 SQLite 文件，由模型用终端查库并交 SQL | 53/101（52.48%） | 96 份 SQL |
| 改进自主查库提示 | 开场说明怎样接续追问、怎样交付，后续逐轮发原题 | 75/101（74.26%） | 100 份 SQL |
| 由 MCP 交付结果 | 模型自主查库，MCP 执行最终 SQL，直接交结果表 | 66/101（65.35%） | 98 张表 |

原规则用 SQLite 执行模型 SQL 和参考 SQL，比较完整结果。第 5 种做法另有 3 问提出澄清。 [101 问逐题对照](evidence/week-03/paired-101.csv)

### 从试跑到 502 问

**32 问跑通 → 27 问试连续提问 → 同题 101 问对照 → 300 问 → 502 问。** 连续提问用于保留上轮结果，自主查库用于核实真实字段和值，MCP 用于直接交付查询结果。建表语句、字段值样例和脚本代查各在同一批 25 问做过小测。 [实验过程](weeks/week-03/README.md#实验怎样推进)

| 同一批 502 问，按什么给分 | 连续提问基线 | 自主查库 + MCP |
| --- | ---: | ---: |
| 按参考 SQL 的完整执行结果 | 343/502（68.33%） | 325/502（64.74%） |
| 按题意与原库事后复评 | 458/502（91.24%） | **492/502（98.01%）** |

新版在完整结果比较中少通过 18 问，在题意复评中多通过 34 问。战役日期多带一列战役名，复评能给分。航班查询与参考都返回 0，原库查出 3 班，复评会撤分。 [判分过程](weeks/week-03/cases.md)
